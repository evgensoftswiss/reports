# Weekly Planner Frontend 0.4.8

## Изменения 0.4.8

- Внешние отступы страницы «Загруженность команды» приведены к отступам
  пользовательского и менеджерского разделов.

## Изменения 0.4.8

Отчёт встраивается в страницу через API HTML-фрагмента, без iframe.

Статический HTML/JS-интерфейс для размещения на GitHub Pages.

Версия `0.4.5` автоматически открывает последний успешно сформированный отчёт
при входе в раздел и ограничивает время ожидания запросов, чтобы интерфейс не
зависал бесконечно при сетевой или серверной ошибке.
Футер показывает версии интерфейса и API; версия API загружается из `/health`.

Версия `0.4.3` используется вместе с API 0.4.3. Из формы формирования отчёта
удалены название и ручной список email: пользователи берутся API из
`config/whitelist.json` → `users`.

Версия `0.4.2`: сформированный сервером отчёт
показывает время нарушения SLA над Target start/End, красное состояние нарушения
и подробный попап со всеми SLA-метриками и циклами.

Опрос фонового задания ограничен 30 минутами: при проблеме сервер больше не оставляет интерфейс в бесконечном состоянии ожидания.

- Удалена кнопка «Открыть отчёт»; отчёт остаётся встроенным в страницу.
- Заголовок «Отчёт по загруженности» ведёт на `https://evgensoftswiss.github.io/reports`.
- Пользовательская, менеджерская и отчётная части используют единое оформление `PLANNING`.

Версия `0.4.0` добавляет менеджерский раздел `workload.html` для формирования
JIRA-отчёта через существующий Weekly Planner API. Клиент не содержит Jira- или
GitHub-токенов, использует существующие Google Sign-In/JWT и не сохраняет
открытые данные отчёта в GitHub Pages.

## Перед публикацией

В `config.js` указать Google OAuth Client ID:

```js
GOOGLE_CLIENT_ID: "...apps.googleusercontent.com"
```

## Текущие возможности

- Google Sign-In;
- вход только для email из серверного whitelist;
- автоматическое определение роли `user` или `manager`;
- загрузка доступных периодов;
- рабочий интерфейс Planner 0.2.13;
- рабочий интерфейс Manager 0.1.3;
- чтение и сохранение собственного зашифрованного плана;
- менеджерский список пользователей, общий план и распределение задач;
- менеджерский JIRA-отчёт по загруженности с режимами кеш/сегодня/force;
- access token хранится только в памяти вкладки.

Legacy HTML сохранён внутри проекта без серверной части. `planner.html` и `manager.html` загружают рабочие интерфейсы только после проверки API-сессии.

Версия 0.1.1 гарантированно загружает `config.js` и `auth-bridge.js` до запуска legacy-интерфейса. Благодаря этому относительные запросы `/api/...` всегда направляются в Weekly Planner API, а не в GitHub Pages.

Версия 0.1.2 автоматически заполняет строку `Communication` в плане следующей недели: `Hours` содержит сумму длительности встреч, а `Comment` — названия встреч с длительностью в десятичных часах.

Версия 0.1.3 перенаправляет на страницу входа при ответе API `401 Unauthorized`, показывает версию интерфейса на каждой странице и принудительно пересчитывает `Communication` перед отображением и сохранением плана. Старое сохранённое значение этой строки не используется.

Версия 0.1.4 добавляет в менеджерскую часть круговую SVG-диаграмму распределения часов по стримам. Название и часы показываются при наведении, а сектор плавно выдвигается от центра.

Версия 0.1.5 сворачивает длинный комментарий Communication и объединяет одинаковые названия митингов с суммированием часов.

Версия 0.1.6 добавляет проценты в планы и диаграмму, кнопку выхода в профиле пользователя и компактное распределение задач без горизонтального скролла.
